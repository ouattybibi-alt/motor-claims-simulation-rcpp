# Motor Insurance Claims — Monte-Carlo Simulation and R/C++ Interfacing

Monte-Carlo estimation of the conditional expected excess loss for a policyholder portfolio, combining rejection and inversion sampling for the reimbursement distribution, a Markov-chain weather driver, and an R-to-C++ interface for the most compute-intensive routine.

Academic project (Master 1 Actuariat, ISFA — Simulation), Co-authored with C. A. D. Kouamé and S. Ouattara.

## What this project does

### 1. Reimbursement random variable `rremb`

The reimbursement per accident follows a piecewise density with a discontinuity at α. Two independent implementations:

- **Rejection sampling** — uniform envelope with dominance constant, straightforward but wasteful when the target has a peaked mode
- **Inversion sampling** — closed-form derivation of the CDF F, then analytic inversion of F⁻¹ with a piecewise simplification

Both are benchmarked on execution time and validated by histogram comparison.

### 2. Weather Markov chain (`simulate_weather_vectorised`)

Weather over 100 years is generated by a vectorised Markov-chain sampler. Accident probability is state-dependent (higher under rain), which propagates into the loss distribution.

### 3. Conditional expected excess — `msa` and `msb`

Estimation of *m(s) = E(R − s | R > s)*, the expected excess loss above threshold s:

- **`msa`** — direct Monte-Carlo: simulate R, filter on R > s, average the excess
- **`msb`** — alternative estimator addressing the sample-loss inefficiency of `msa`: rebuilds the excess above s from a conditional reparameterisation, keeping every simulated draw useful

Both estimators are implemented in R and compared on the same set of parameters (α, x₀, η, accident probability in rainy vs sunny weather).

### 4. R ↔ C++ interfacing (`msb.c`)

The `msb` estimator is ported to C in five parts and called from R via the C API. The wall-clock speedup is measured on two representative parameter sets and reported side by side with the pure-R timings.

### 5. Model analysis

- Parameter sensitivity: rain-accident probability, x₀, η
- Range of application: when the model is well-suited vs when it breaks
- Improvement paths discussed in the conclusion

## Why this matters

Beyond the actuarial content, the project demonstrates two things a quant profile looks for: a **clean numerical methodology** (rejection vs inversion, direct vs alternative Monte-Carlo estimators, all with timing comparisons), and **hands-on experience with the R/C++ interface** that is standard in banks and insurers wherever an R prototype meets a production performance requirement.
